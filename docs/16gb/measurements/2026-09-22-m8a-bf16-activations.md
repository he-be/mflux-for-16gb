# M8a: DiT の活性を bf16 にする → **合格**(1 ステップ 21.2 → 13.1 s、画像は同等)

- 測定日: 2026-09-22
- 機材: Mac mini (Apple M6) 16GB、macOS 27.0、MLX 0.32.0
- 実装: `a8e7423` + `krea2.py` の `_predict`(ストリーミング経路で `ModelConfig.precision` に cast)
- 根拠: [M8](2026-09-22-m8-block-profile.md)、[計画](../../.cursor/plans/2026-09-22-krea2-dit-speed.md) §M8a
- 再現: M7 §3 と同じコマンド(`--block-streaming`)

## 0. 結論

| | M7(float32) | **M8a(bf16)** | |
|---|---|---|---|
| 1024² 1 ステップ | 21.22 / 20.91 s | **13.08 s** | **1.62 倍** |
| 　計算 / ブロック | 610.3 / 607.7 ms | **328.6 ms** | 1.86 倍 |
| 　I/O / ブロック | 146.8 / 138.2 ms | 137.3 ms | 変わらず(直列のまま) |
| 　計算 ÷ I/O | 4.16 | 2.39 | 合格基準 2.0 はまだ超える |
| 　footprint | 5.32 / 5.26 GB | **5.26 GB** | |
| 1280² 1 ステップ | 35.21 s | **19.08 s** | **1.85 倍** |
| 　計算 / ブロック | 1118.1 ms | **541.6 ms** | 2.06 倍 |
| 　footprint | 6.46 GB | 6.46 GB | |
| swapouts / verdict | 0 / clean | **0 / clean**(2 本とも) | |

M8 のブロック単体の予測(320 / 560 ms、13.1 / 19.5 s)と 1〜3% で一致。

変更は 1 か所。`Krea2._predict` で、ストリーミング経路のときだけ latent を
`ModelConfig.precision`(bf16)に落として transformer に渡し、戻りの速度場を latent の
dtype(float32)に戻す。ノイズとサンプラは float32 のまま。トレーニング側の
`Krea2TrainingAdapter` が元からやっている cast と同じ。

常駐経路(`--block-streaming` なし)は float32 のまま。upstream の golden テスト
(`tests/image_generation/test_generate_image_krea2.py`、要 26 GB の bf16 ウェイト)を
この環境では再生成できないので、そちらの数値を動かさないため。

## 1. カーネルの確認

`tools/bench/qmm_spy.py` で 1 ステップの `quantized_matmul` を全部記録:
515 回すべて **bfloat16**(M7 §4 では DiT の 224 回が float32 だった)。
4110 トークンの 225 回(28 ブロック × 8 + `first`)が bf16 の `nax` カーネルに落ちる形。

## 2. 画像判定

M7 の同一機材の画像(`images/20260922-1414-m7-m6mini-1024.png`、`-1423-...-1280.png`。
M7 §5 で同一機材の 2 回が完全一致することを確認済み)と比べる:

**bf16 化の差は、機材を変えたときの差より小さい。** 目視: 構図・被写体・光は同一、
描き込みの量も同等(ヘルメットの錆・窓の水滴・作業台の埃まで同じ)。1280² では
左下の小物 1 つの形が少し違う(円筒 → 角ばった塊)程度で、画としての差はない。
