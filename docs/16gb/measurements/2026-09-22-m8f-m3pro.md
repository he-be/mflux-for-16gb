# M8f: M3 Pro 18GB での回帰 → **合格**(29.6 → 23.0 s/step、footprint 5.21 → 4.66 GB)

- 測定日: 2026-09-22
- 機材: MacBook Pro (Apple M3 Pro) 18GB、macOS 15.6、MLX 0.32.0、`iogpu.wired_limit_mb=15360`(M6 と同条件。既定 0 での再測定は依然として未実施)
- 実装: 最終構成(M8a + M8b + M8d)
- 再現: M6 §実行のしかた と同じコマンド(1024²)

| | M6(float32、M3 Pro) | **M8f** | |
|---|---|---|---|
| 1 ステップ | 29.60 s | **22.96 s** | **1.29 倍** |
| 計算 / ブロック | 976.9 ms | 818.6 ms | 1.19 倍 |
| 見えている I/O | 71.9 ms | **0.7 ms** | 裏の読み 72.6 ms(計算 ÷ 読み 11.3) |
| footprint | 5.21 GB | **4.66 GB** | −0.55 GB(M8d の cache limit) |
| swapouts / verdict | 56 ページ(外来)/ clean | **0 / clean** | |

M3 Pro には neural accelerator がないので bf16 の効きは小さい(q8 matmul が
float32 4.69 → bf16 5.10 TFLOPS)。それでも attention の float32 → bf16 と、
I/O を隠した分で 1.29 倍。**M3 Pro でも遅くならず、footprint は減る。**

M3 Pro では bf16 化の差(4.70)が M6 mini(1.55)より大きく、float32 の機材差と同じ桁。
目視では構図・被写体・光・描き込みとも同一(`images/20260922-1540-m8f-m3pro-1024.png`)。
**bf16 同士なら機材をまたいだ差が 4.6 → 1.55 に縮む**のは意外な副産物で、
float32 の経路では nax の有無で累積順が大きく違っていたということ。
